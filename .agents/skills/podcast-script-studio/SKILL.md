# 播客脚本生产工坊

你将帮用户生产一档**双人（或三人）对话式知识型播客**的节目脚本。本技能的方法论来自对一档高水准中文历史类播客 56 期节目的逐期分析，核心成功公式是：

> **用茶馆式双人聊天作外壳，装"学者级知识 + 常人化翻译 + 人性洞察"的内核，以认知反差为钩子、以概念工具为交付物。**

## 底层哲学：风格来自浸润，不来自执行清单（最高优先级）

那档节目为什么好听？因为两个博学的人**真的在聊**——旁征博引、信马由缰、讲到哪岔到哪、互相接梗、岔出去还能绕回来。它的魅力大半来自**没被设计过的部分**。因此本技能的用法有一条铁律：

- **`references/06-style-samples.md`（真实语料样本）是最高权威**。动笔前通读它，让那两个人的语感"上身"，然后像他们一样聊天式地写——不是执行技巧清单。
- references 里的所有技巧、结构、模板，是**风格基因库与防坑地图**，不是创作配额。所有数字（字数、占比、功能分布、时长）都是**对原节目的统计描述，照着写时仅供参考，绝不机械执行**。宁可生动而结构松散，不可结构完美而死气。
- **发挥优先，规则兜底**：鼓励枝蔓（讲到 A 岔到 B 的典故再绕回来）、荒诞接龙、即兴式跑偏——这些"越界"正是原节目被验证过的魅力来源，本技能的"合法跑偏"等技巧就是为它们撑腰的。规则只在三种情况出手：事实错误、剧本腔/书面腔、违背单一真相源等工艺底线。

参考画像（统计描述，非配额）：原节目成品 30-60 分钟、主讲话轮长、主持话轮短、话轮交换频繁；本档按用户定位约 30-40 分钟。

## 角色设定

脚本围绕两个固定角色展开（首次使用时向用户确认节目名与角色名，之后沿用）：

- **主讲**（学者型）：知识输出、观点判断、自嘲。话轮长（100-150 字/轮），敢于下判断但保持谦逊姿态。
- **主持**（真实对话者）：不是捧哏，是**带着真实困惑的提问者**。话轮短，承担九种功能——复述确认（"所以是不是就可以理解为……"）、代听众发问、金句接梗补刀、拉回主线、推进转场、争议逼问、个人叙事，以及两处进阶功能：立场口径确认（敏感话题替听众问"所以你们的立场到底是？"）、听众共创（把评论区反馈/纠错引入正片）。
- 可选**嘉宾**（专家型）：按选题邀请（医药史请中医、军事史请军迷），功能是知识合法化 + 提出不同观点制造内部辩论。

首次为用户工作时：**先检查用户项目 `podcasts/节目档案.md` 是否存在**——存在则直接沿用其中的节目名、主播名与人设、音色映射、凭据位置，跳过提问；不存在则询问三件事并建议把答案写进该档案（节目名与主播名 / 题材与听众 / 有无往期节目与已挖的坑）。

## 工作流：五个阶段，按需进入

用户的需求决定入口。判断不清时直接问："你现在需要的是 A 选题策划 / B 节目大纲 / C 完整脚本 / D 打磨已有稿子 / E 音频合成与成品输出？"

### 阶段 A：选题策划 → 产出《选题卡》

输入：一个模糊想法、一个热点、一个领域，甚至"帮我想选题"。

1. 读 `references/01-topic-selection.md`（选题七型 + 标题九型公式）与 `references/09-reference-shows.md`（已验证选题全景 + 可接手的选题方向库——避重、借鉴、直接取用）。
2. 用 `assets/topic-card-template.md` 的模板产出选题卡，一卡一期。选题卡必须包含：**认知反差点**（"你以为的 vs 实际上的"——这是选题生死线，没有反差就先反推选题）、题型判断、标题候选 3-5 个、核心问题、听众共鸣点、角色/嘉宾配置、冷开场候选片段方向。
3. **深度挖掘**（选题卡"内容弹药"栏的作业流，方法见 `references/08-research-method.md` 五步：误解清单→素材四层挖掘→主线结构假设→概念工具锻造→对垒观点），弹药深度检验不通过不进阶段 B。
4. 若用户要批量选题：围绕一个领域产出 5-8 张卡，覆盖不同题型（系列型、热点型、网感概念型、争议站队型……），并标注哪些可组成系列。

### 阶段 B：结构设计 → 产出《节目大纲》

1. 读 `references/02-structure.md`（五段骨架 + 八大题型主体模板 + 节奏控制）。
2. 按选题卡判定的题型选主体模板，产出带时间轴的分段大纲：每段标注时长目标、内容要点、悬念/笑点/合法跑偏的预定位置、冷开场选段、结尾菜单内容。
3. 大纲需通过自检：每 3-5 分钟有一个梗锚点；每 10 分钟左右一次转折/换板块；至少安排 1 处合法跑偏（共鸣密集区）；至少 1 把"可带走的尺子"（概念工具）。

### 阶段 C：脚本撰写 → 分幕产出《完整脚本》

1. 先读 `references/03-dialogue.md`（话轮功能库）和 `references/06-style-samples.md`（风格样本库，写作时反复对照语感）。
2. **分幕撰写**：按大纲一次写一幕（净台词约 2700-3900 字，对应约 7-10 分钟成品），写完一幕给用户确认再继续。四幕合计即 30-40 分钟目标。一次性写完全部必然质量崩塌，禁止。
3. 对话稿格式：说话人标注 + 估算时间戳，见 `assets/script-format-template.md`。
4. **当下翻译，分级适用**：生疏之物三级处理——A级（主线论证依赖的概念/制度/理论/数据）必译，走 `references/04` 第二节的七种模式（制度→现代组织、职务→现代岗位、事件→现代场景、理论→身体经验、博弈→游戏语言、数据→具象锚、处境→普遍人性）；B级（叙事性生疏词）语境化即可；C级（不影响理解的专名）放过。警惕过度翻译（拆节奏/显得说教/类比贬值）。理论概念另走完整**学术降维三步法**（原文→吐槽→比喻→回扣），每期至少完整执行 2 次。
5. 语言与幽默按 `references/05-language-humor.md` 的工艺执行：金句要"对偶反转/极端化判断/一句话制度翻译"；现代梗每 3-5 分钟一个锚点；反讽成语、荒诞类比接龙、游戏语言按库取用。

### 阶段 D：质检打磨 → 产出《质检报告》+ 修订稿

用 `assets/quality-checklist.md` 逐项检查（钩子强度、反差点是否落地、降维三步法覆盖率、话轮比例、金句密度、主持功能多样性、结尾菜单……），输出通过/不通过清单和修订建议，然后改稿。

### 阶段 E：音频合成 → 成品播客（mp3 + srt）

用户要"把脚本变成音频/成品"时进入。**先读 `references/07-audio-production.md`**（本阶段完整指南）。核心流程：

1. `scripts/md_to_timeline.py` 把各幕 md 转成时间脚本 txt（**md 是唯一源稿，改台词只改 md**，txt 永远是生成物）
2. `scripts/doubao_podcast_pipeline.py` 调豆包播客 API（action=3 指哪打哪模式：逐轮指定说话人+文本，服务端逐字合成不改写）。凭据用 `--creds-file`/`--appid --token`/环境变量，由用户提供
3. 整期配置：幕1 只留片头音乐、中间幕无音乐、末幕只留片尾音乐，最后 `scripts/concat_episode.py` 拼接（音频合并 + 字幕时间轴偏移）
4. 验收：正反向文本抽查 + 幕间衔接试听

修订分层（用户问"改句子要重做吗"）：改 md→重跑该幕→重拼接（默认，约 3 分钟）；句级补丁；只改字幕用 `scripts/rebuild_srt.py`（不动音频）。

## 创作铁则：先自由地写，再用底线兜底

写作的正确顺序：**先通读 `06-style-samples` 让语感上身，然后像那两位主播一样自由地聊着写**（旁征博引、枝蔓、接龙、跑偏都放开），写完再对照下面的底线清单兜底。底线上的一切发挥空间都不受限制——下方 A 组是防翻车的底线（硬性），B 组是风格倾向（软性，为生动性服务而非约束）。

**A 组·工艺底线（硬性）：**

1. **事实纪律**：历史/知识内容标注史料出处（正史/野史/网友观点/影视改编分开）；"正史 vs 演义"要明示；不确定的信息用概率化表述，禁止把猜测写成定论。
2. **禁止剧本腔（主播不知道自己活在剧本里）**：台词里绝不出现任何暴露"这是被编写/被结构化"的词汇——包括但不限于：**第X幕/这一幕/下一幕/上幕/几幕/四幕/一幕/开幕/落幕、伏笔、回收、彩蛋、板块、环节、章节、大纲、脚本、文案、收束段、结尾菜单**。转场一律用内容本身衔接（"先说他的失败""最后说那八个字"）。**例外**：节目社群黑话（挖坑/填坑/催更/课代表）是原节目主播自己的口头禅，合法。**强制自查**：每幕写完机械执行 `grep -n "幕\|伏笔\|彩蛋\|板块\|环节\|回收\|收束" 幕文件`，逐条裁决（"夜幕"等自然语也建议换词，零容忍最省心）——v5 实战教训：写作时自觉绕开了"下一幕"，却写出"今天四幕""埋个伏笔""埋个彩蛋"这类变体，人肉记忆靠不住，必须机械扫描。
3. **禁止书面腔**：这是要说出来的稿子。允许"这个事吧""你就想啊""说白了"；句子短；避免书面语与四平八稳的排比。
4. **主持人不是捧哏**：主持每轮话要承接上一轮具体内容（追问/复述/接梗/讲自己），禁止纯应和（"对""是的""嗯"单字轮）。
5. **分寸底线**：吐槽有爱、刻薄有度；沉重话题一句带过不消费；敏感题材配立场双轨声明、幽默对象隔离（详见 04/05）。
6. **单一真相源**：台词修改只改 md 源稿，txt 用 `scripts/md_to_timeline.py` 重新生成，严禁手改。

**B 组·风格倾向（软性，统计自原节目，服务于生动，不用于限制）：**

7. 认知反差（"你以为的 vs 实际上的"）是好选题的共性基因——选题时用它自检，而非写作时机械植入。
8. 观点姿态：敢下判断+概率化表达（"我认为概率最大""不好说"）；争议给平衡；预测只给可能性清单。
9. 结构是"骨架"不是"轨道"：冷开场+报幕缘由+主体+收束+结尾菜单是常形，但原节目也常不守常形（连载直接书接上回、情怀期放歌收尾）——形态服务于内容。
10. 跑偏是魅力不是事故：旁征博引的枝蔓（讲到 A 岔到 B 的典故/掌故/生活经验再绕回来）多多益善，主讲自我觉察式拉回（"话题扯远了"）是收束技巧不是配额。
11. 以古鉴今：知识尽量能落到听众生活（一两句点到即可），结尾常有一个可带走的工具或行动——但故事与畅聊永远优先于"应用栏目"（v3 教训：说教压死生动性）。

## 完成一期的标准

- 选题卡：反差点清晰、标题可用、题型明确
- 大纲：时间轴完整、节奏点标注、跑偏与路牌就位
- 脚本：冷开场有钩子（可含结尾金句形成环形）、主体按题型模板推进、降维三步法至少完整执行 2 次、主持话轮多功能齐备、结尾菜单完整（总结回扣+告别恒在）、全文口语可读（朗读测试通顺）
- 质检：清单全项通过或已说明豁免理由
- 音频（若做阶段 E）：md→txt 链路一致（转换器重生成比对通过）；SRT 无剧本腔/尾注/旧句残留（正反向抽查）；幕间衔接试听干净；字幕条数 = 各幕话轮数之和
