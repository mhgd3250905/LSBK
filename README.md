# 笑谈历史（LSBK）——播客全流程生产仓库

《笑谈历史》是一档双人历史对谈播客：**大开**（主讲，说书人视角）× **小李**（主持，好奇听友视角），主打"正史细节的戏剧性冲撞 + 打穿古今的人性命题"。本仓库承载从选题策划、史料核对、文稿写作、TTS 音频合成到小宇宙平台发布的完整生产链路与全部文本资产。

> **给接手 Agent 的话**：本仓库为 AI 协作而整理。你不需要跑通音频管线也能贡献核心价值——**选题策划与文稿写作只依赖 Markdown 文本资产**。请按下方"接手上手顺序"阅读，严格遵从各规范文档，发布类动作必须获得用户明确授权。

## 接手上手顺序（新会话必读，约 15 分钟）

1. **`AGENTS.md`**（仓库根）——工作区总则，多数 Agent 框架会自动加载
2. **本 README**——项目结构与协作边界
3. **`podcasts/节目档案.md`**——班底/音色定则/选题池/每期档案，**选题协作的唯一入口**
4. **`podcasts/AI书写规范.md`**——写作与去 AI 化规则的唯一汇总（硬禁令 + 取向引导两档力度，先读再动笔）
5. **`podcasts/发布SOP与台账.md`**——发布七步流程 + 18 条实战踩坑 + 每期发布记录（含各期单集 ID）
6. 任选一期成品对照学习，推荐 `podcasts/EP18_黑衣宰相姚广孝/`（选题卡 → 史料核对 → 大纲 → 四幕脚本 → 质检报告 → shownotes 全套范式）

## 你可以协助什么

| 工作类型 | 入口 | 说明 |
|---|---|---|
| **选题策划** | `节目档案.md` 的"已挖的坑"选题池 | 按选题三要素提案（血肉主角 / 正史名场面 / 人性命题），参考任一期 `选题卡.md` 的格式与"九型公式选优"标题法 |
| **文稿写作/修订** | 目标期目录 + `AI书写规范.md` | 写前必读规范；成稿跑规范第六节机械自查命令 |
| **审核复盘** | `制作与文稿审核_*.md` | 事实边界核查、去 AI 化体检 |
| **发布执行** | `发布SOP与台账.md` | ⚠️ 仅在用户明确授权后操作；涉及平台账号与登录态 |
| **音频合成** | 根目录 TTS 管线脚本 | 需要本地凭据与 ffmpeg 环境，见下"环境依赖" |

## 目录结构

```text
podcasts/                    # 核心：每期一套完整资产目录
  EP01_.. ~ EP21_../           #   选题卡/大纲/史料核对/脚本_第N幕/质检报告/
                               #   shownotes.md/封面png/make_cover.py/output(srt等)
  节目档案.md                  #   班底、选题池、发布档案（单一事实源）
  AI书写规范.md                #   写作/去AI化规则唯一汇总
  发布SOP与台账.md             #   发布流程、踩坑档案、发布记录
  制作与文稿审核_*.md          #   历次审核复盘（规则背景，不再增量维护）
  archive_*/                   #   已归档不发布的弃用选题
doubao_podcast_pipeline.py   # 豆包 TTS 双人播客合成管线（批请求/时间轴/SRT）
concat_episode.py            # 四幕音频拼接 + SRT 时间轴偏移合并
audit_voice.py               # 双人音色纯度体检（基频自相关）
rebuild_srt.py / patch_ep04.py / md_to_timeline.py 等  # 字幕重建/句级补丁/稿转时间脚本
analysis/ · doubao_sdk_ref/  # API 调研笔记与 SDK 参考（已脱敏）
.agents/skills/              # podcast-script-studio（制作技能）、humanizer-zh（润稿技能）
```

**注意**：音频成品（mp3）与 API 凭据**不入库**（见 `.gitignore`）。clone 后没有音频文件属正常；字幕 SRT、时间轴 JSON 等元数据齐全。

## 环境依赖（仅音频/发布相关操作需要）

- Windows + Git Bash；Python 3.10+；ffmpeg/ffprobe
- 豆包（火山方舟）播客 TTS API——凭据在本地 `豆包api.txt`（被 gitignore，需用户另行提供）
- 小宇宙发布走 Playwright 自动化（登录态在用户浏览器 profile，见台账踩坑档案）

## 版本管理约定

- 发布完成、规范变更或重要物料定稿后随手 commit；消息风格：`feat(EPxx): ...` / `docs: ...`
- 台账与节目档案里引用的历史 commit SHA 均真实可溯，**不要改写历史**
- 本仓库 remote 为 GitHub 私有库；push 前确认无凭据类文件混入（`.gitignore` 已覆盖 `*token*`/`*secret*`/`*creds*` 等模式）

## 硬红线（违反即返工）

1. 不虚构史实、对白、动机、私密场景、听众反应——先锁证据再定故事；
2. 正文直接引号为零（引语一律第三人称转述）；纯双人声线，不设第三音色；
3. 不把凭据、登录态、音频成品提交进 git；
4. 未经用户明确授权不执行平台发布/删除操作；
5. 写作规则以 `podcasts/AI书写规范.md` 为准——其中"零容忍"条目是用户逐条点名过的，其余是取向引导，不要把引导执行成死板禁令。
