# 笑谈历史（LSBK）——播客内容与选题协作仓库

《笑谈历史》是一档双人历史对谈播客：**大开**（主讲，说书人视角）× **小李**（主持，好奇听友视角），主打"正史细节的戏剧性冲撞 + 打穿古今的人性命题"。本仓库承载节目全部**内容资产与创作知识**：选题策划、史料核对、文稿、审核规范与发布记录。

> **给接手 Agent 的话**：本仓库为 AI 协作而整理，只含文本与封面等内容资产，**不涉及音频制作**（TTS 合成管线、音频分析与转写工具链在维护者本地，不在本仓库）。你在这里能做的核心工作是**选题策划与文稿协作**。请按下方顺序阅读，严格遵从各规范文档；任何发布类动作必须获得用户明确授权。

## 接手上手顺序（新会话必读，约 15 分钟）

1. **`AGENTS.md`**（仓库根）——工作区总则，多数 Agent 框架会自动加载
2. **本 README**——项目结构与协作边界
3. **`podcasts/节目档案.md`**——班底/选题池/每期档案，**选题协作的唯一入口**
4. **`podcasts/AI书写规范.md`**——写作与去 AI 化规则的唯一汇总（硬禁令 + 取向引导两档力度，先读再动笔）
5. **`podcasts/发布SOP与台账.md`**——发布流程 + 18 条实战踩坑 + 每期发布记录（含各期单集 ID 与上线状态）
6. 任选一期成品对照学习，推荐 `podcasts/EP18_黑衣宰相姚广孝/`（选题卡 → 史料核对 → 大纲 → 四幕脚本 → 质检报告 → shownotes 全套范式）

## 你可以协助什么

| 工作类型 | 入口 | 说明 |
|---|---|---|
| **选题策划** | `节目档案.md` 的"已挖的坑"选题池 | 按选题三要素提案（血肉主角 / 正史名场面 / 人性命题），参考任一期 `选题卡.md` 格式与"九型公式选优"标题法 |
| **文稿写作/修订** | 目标期目录 + `AI书写规范.md` | 写前必读规范；成稿跑规范第六节机械自查命令 |
| **审核复盘** | `制作与文稿审核_*.md` | 事实边界核查、去 AI 化体检 |
| 发布执行参考 | `发布SOP与台账.md` | 流程与踩坑可读可参考；实际发布需用户在本地环境授权执行 |

## 目录结构

```text
podcasts/                    # 核心：每期一套完整内容资产
  EP01_.. ~ EP21_../           #   选题卡/大纲/史料核对/脚本_第一~四幕/
                               #   质检报告/shownotes.md/封面png/make_cover.py
  节目档案.md                  #   班底、选题池、发布档案（单一事实源）
  AI书写规范.md                #   写作/去AI化规则唯一汇总
  发布SOP与台账.md             #   发布流程、踩坑档案、发布记录
  制作与文稿审核_*.md          #   历次审核复盘（规则背景，不再增量维护）
  archive_*/                   #   已归档不发布的弃用选题
  宋朝系列/                    #   宋朝大合集规划 + 各期选题卡/史料核对（未制作）
  提案_张璁/                     #   单期选题提案（选题卡就绪，待批准立项）
AGENTS.md                    # Agent 工作总则
```

各期目录内的 `第一~四幕_时间脚本.txt` 与 `shownotes.md` 的时间轴均为音频成品实测数据，可直接用于校对节奏与章节。

## 版本管理约定

- 本仓库为**内容快照视图**：维护者本地保有完整生产工作区（含音频制作），按里程碑将内容层同步至此
- 规范变更、新期定稿、发布记录更新后随手 commit；消息风格：`feat(EPxx): ...` / `docs: ...`
- 不要提交凭据、登录态、音频文件（`.gitignore` 已覆盖）

## 硬红线（违反即返工）

1. 不虚构史实、对白、动机、私密场景、听众反应——先锁证据再定故事；
2. 正文直接引号为零（引语一律第三人称转述）；纯双人声线，不设第三音色；
3. 不把凭据、登录态提交进 git；
4. 未经用户明确授权不执行平台发布/删除操作；
5. 写作规则以 `podcasts/AI书写规范.md` 为准——其中"零容忍"条目是用户逐条点名过的，其余是取向引导，不要把引导执行成死板禁令。
