# 播客脚本生产工坊

你将帮用户生产一档**双人对话式知识型播客**的节目脚本。外部中文历史播客的分析提供可借鉴的技法；实际创作以用户节目《笑谈历史》的节目档案、已有脚本中经核实的高光片段和真实反馈为准。

> **让两位主播围绕有据可查的事件交换认识：讲明白史实，也给听众留下可讨论的问题。**

## 底层哲学：风格来自浸润，不来自执行清单（最高优先级）

好听的对话要让两个人确实在交换认识：一方提出有据的解释，另一方带着问题、不同材料或自己的判断进场，必要时两人都能修正说法。因此本技能的优先顺序是：

- **先对齐本节目声音**：查 `podcasts/节目档案.md`、项目最新的 `podcasts/制作与文稿审核*.md` 和本节目已核实的高光片段，辨认大开、小李各自如何讲故事、质疑和接梗。`references/06-style-samples.md` 是另一档节目的节奏参考，不照搬其词句、口癖、经历或立场；用户明确点名的上一期或偏好样稿优先。
- **证据先于反转**：冷开、标题、关键转折先核来源；事实、基于证据的推断、节目演绎分开。不能为了戏剧性补造历史对白、心理活动、主播亲历或听众反馈。
- **数字只作诊断信号**：references 里的字数、话轮占比、金句、梗、功能、时长和幕数是观察样本时的画像。仅在稿子显得拖沓、偏科或单调时用来定位问题，不作为通过门槛。允许自然跑偏，但每条枝蔓应让听众更理解人物、事件或两位主播。

参考画像（统计描述，非配额）：原节目成品 30-60 分钟、主讲话轮长、主持话轮短、话轮交换频繁；本档按用户定位约 30-40 分钟。

## 撰稿规范与五维自检卡（唯一规范入口，最高效力）

文稿写作、去 AI 化与结构的一切规则以用户项目 `podcasts/AI书写规范.md` 为**唯一规范入口**（规则修订先改它）；本技能与 references 若与其冲突，一律以规范为准。动笔前必读，当前效力最高的部分：

- **影视化叙事宪章（2026-10-14 最高指示）**：坚决消灭论文式对账流水账。首选大主角命运叙事（一个血肉主角的生死起伏折射时代变局），备选绝对话题中心推演；冷开场必须影视级至暗/冲突名场面；考据留在史料核对，人性与戏在台前。
- **单幕五维自检卡（每幕写毕必做）**：按规范 §六输出五维自检卡（大主角贯通/影视化结构/机械零容忍/真实对谈感/自动化脚本），并运行 `python scripts/verify_act_script.py 幕文件.md [--is-last-act]`，**扫描全 0 违规才允许进入时间脚本转换与音频合成**。
- **角色登场人情破冰与零空降（2026-10-21 最高指示·规范第11条）**：严禁生僻人物无铺垫空降或小李背诵百科履历。凡出场人物必先确立人情生态位与心理底座，小李代听众发问，大开具象白描带活；非核心功能性人物坚决去姓名化。
- **历史礼制与反演义黑话底线（2026-10-21 最高指示·规范第12条）**：严守正史礼制规制，严禁称非皇帝人物为“万岁”、“万万岁”或“九千九百岁”；称谓与制度严格遵照正史（如“山呼九千岁，恭祝厂臣千秋”、东厂抓人凭“驾帖”）。
- **末幕双人闭环收口**：仅全集最后一幕末尾执行三轮闭环（小李全期回扣与情感沉淀 → 大开一句话历史注脚 → 小李标志性电台告别语）；前置各幕严禁提前告别或阶段总结；启动合成前人工核验最后一幕最后 3 个话轮。
- **机械零容忍底线**：正文直接引号为 0、小李句首"大开，"为 0、机械对仗句式/AI 禁词套话/政论作文腔/论文腔过渡词/问卷式预设垫话/剧本结构元词汇为 0（点名清单见规范 §三与 §六维度三；脚本只拦点名形态，变体须人工兜底扫描）。

## 角色设定

脚本围绕两个固定角色展开（首次使用时向用户确认节目名与角色名，之后沿用）：

- **主讲**（学者型）：提出有来源的知识和判断，能解释证据的限度，也能被新证据推动修正。话轮长短由内容决定。
- **主持**（独立对话者）：有自己的认识起点，能带来另一份材料、一个误读或不同判断；复述、追问、接梗和转场按对话需要使用。亲历和听众反馈只有真实可核实时才能写入。

**固定双人，不设第三角色（2026-09-21 定稿）**：全节目只有主讲与主持两位说话人（如《笑谈历史》大开×小李），不设嘉宾/第三人/旁白音色。历史人物的话一律由二人以第三人称转述（"张璁说，……"）。方法论中残留的"嘉宾/三人局"字样是对参考节目（三人制）的事实记录，不构成产出指引。

首次为用户工作时：**先检查用户项目 `podcasts/节目档案.md` 是否存在**——存在则直接沿用其中的节目名、主播名与人设、音色映射、凭据位置，跳过提问；不存在则询问三件事并建议把答案写进该档案（节目名与主播名 / 题材与听众 / 有无往期节目与已挖的坑）。

## 工作流：五个阶段，按需进入

用户的需求决定入口。判断不清时直接问："你现在需要的是 A 选题策划 / B 节目大纲 / C 完整脚本 / D 打磨已有稿子 / E 音频合成与成品输出？"

### 阶段 A：选题策划 → 产出《选题卡》

输入：一个模糊想法、一个热点、一个领域，甚至"帮我想选题"。

1. 读 `references/01-topic-selection.md`（选题七型 + 标题九型公式）与 `references/09-reference-shows.md`（已验证选题全景 + 可接手的选题方向库——避重、借鉴、直接取用）。
2. 用 `assets/topic-card-template.md` 产出选题卡，一卡一期。写清核心问题、听众为何关心、可核实的事件或人物、固定双人的不同认识起点、标题与冷开方向。认知反差可以作为钩子，但不能预设反转再倒找史料。
3. 按 `references/08-research-method.md` 深挖素材，并建立简明证据卡：关键主张、原始出处、不同解释、证据等级和预期脚本位置。关键转折无证据时换主线。进入阶段 B 前复核冷开候选和题目是否被证据支持。
4. 若用户要批量选题：围绕一个领域产出 5-8 张卡，覆盖不同题型（系列型、热点型、网感概念型、争议站队型……），并标注哪些可组成系列。

### 阶段 B：结构设计 → 产出《节目大纲》

1. 读 `references/02-structure.md`（五段骨架 + 八大题型主体模板 + 节奏控制）。
2. 先写全期发现路径：每段呈现什么事件、由此生出什么疑问、下一份证据怎样改变判断。按需要选用题型模板，标出关键证据、可能分歧和冷开候选；幕数、时长与结尾由内容决定。
3. 大纲自检：听众能跟上因果与时间线；两位主播有各自立场；每次转折由事件或证据推动。梗、跑偏、概念工具和结尾形式按内容取舍，不为填格而放入。

### 阶段 C：脚本撰写 → 分幕产出《完整脚本》

1. 先读 `references/03-dialogue.md`，再核对节目档案与本节目已核实的高光片段；`references/06-style-samples.md` 只供观察节奏。写稿时把证据卡的事实、推断和演绎分别标在创作笔记中，台词用听众能听懂的方式交代边界。
2. **保住全期弧线，分段撰写**：先定全期的发现路径，再按内容适合的段落或幕撰写和自查；每段完成后核对它如何改变听众的认识。需要用户逐幕确认时再逐幕交付，不机械规定四幕或单幕字数。**每幕写毕立即执行《单幕五维自检卡》并跑 `python scripts/verify_act_script.py 幕文件.md [--is-last-act]`，全 0 违规才算该幕完成**（规范 §六）。
3. 对话稿格式：说话人标注 + 估算时间戳，见 `assets/script-format-template.md`。
4. **按需解释知识**：主线依赖的生疏概念必须让听众理解；`references/04-knowledge.md` 的当下翻译和降维法是备选工具，不在台词里报方法名，也不为凑次数反复类比。
5. **写出真实分歧**：小李可以拿相反证据质疑大开的初判，大开必须回应具体证据。允许暂时无解，禁止用“各有道理”遮掉证据权重。幽默按 `references/05-language-humor.md` 取用，以具体情境生长，不塞定量金句。
6. **独立反证审稿后再润稿**：完成初稿先由未参与本段写作的审稿者或独立审稿轮次核对证据卡，专找时间线冲突、无证因果、假引语、假亲历和预设结论；逐条修正后，才用同级 `../humanizer-zh/SKILL.md` 局部清理空话、重复和机械转场。以本节目自身声音校准，保留有效口头重复和两人差异；不得改变事实、来源、数字、条件、否定、判断强度、角色分工或引语转述。只写回 md 源稿。

### 阶段 D：质检打磨 → 产出《质检报告》+ 修订稿

用 `assets/quality-checklist.md` 找错并修订，尤其复核冷开与关键转折、证据分层、两人独立立场和润稿保真。若能安排目标听众盲听，取开头、中段、结尾的文稿朗读小样，记录哪里想继续听、哪里听不懂、哪里像在背稿；文稿阶段无需制作成品音频。不能盲听时由不了解稿件的人盲读并标出停顿与疑问。数字统计只用于诊断，不给“全项通过”掩盖关键错误。

### 阶段 E：音频合成 → 成品播客（mp3 + srt）

用户要"把脚本变成音频/成品"时进入。**进入前置条件：各幕脚本已全部通过五维自检卡与 `verify_act_script.py` 零违规，且末幕已人工核验双人闭环收口（最后 3 话轮）**。先读 `references/07-audio-production.md`（本阶段完整指南）。核心流程：

1. `scripts/md_to_timeline.py` 把各幕 md 转成时间脚本 txt（**md 是唯一源稿，改台词只改 md**，txt 永远是生成物）
2. `scripts/doubao_podcast_pipeline.py` 调豆包播客 API（action=3 指哪打哪模式：逐轮指定说话人+文本，服务端逐字合成不改写）。凭据用 `--creds-file`/`--appid --token`/环境变量，由用户提供
3. 整期配置：幕1 只留片头音乐、中间幕无音乐、末幕只留片尾音乐，最后 `scripts/concat_episode.py` 拼接（合并前剥离豆包逐轮音流中的有效 ID3 标签，并按清理后各幕的实测时长偏移字幕）
4. 验收：整轨无错误解码；正反向文本抽查；幕间衔接试听；双人声部按基频体检结果复核可疑句

修订分层（用户问"改句子要重做吗"）：改 md→重跑该幕→重拼接（默认，约 3 分钟）；句级补丁；只改字幕用 `scripts/rebuild_srt.py`（不动音频）。

## 创作铁则：先自由地写，再用底线兜底

写作顺序：先建立证据卡与全期发现路径，再对照本节目档案和经核实的高光段写双人初稿；随后做独立反证审稿，最后局部润稿。`06-style-samples` 只提供外部节奏参考。下方 A 组是工艺底线，B 组是可按内容取舍的风格倾向。

**A 组·工艺底线（硬性）：**

1. **事实纪律**：关键主张留证据卡，区分可核实事实、依据证据的推断、节目演绎；历史/知识内容标明出处性质与时间线。不确定性按证据强度表达，禁止把猜测、虚构对白与心理活动写成确定史实。主播亲历、社群与听众反馈必须有真实依据。
2. **禁止剧本腔（主播不知道自己活在剧本里）**：台词里绝不出现任何暴露"这是被编写/被结构化"的词汇——包括但不限于：**第X幕/这一幕/下一幕/上幕/几幕/四幕/一幕/开幕/落幕、伏笔、回收、彩蛋、板块、环节、章节、大纲、脚本、文案、收束段、结尾菜单**。转场一律用内容本身衔接（"先说他的失败""最后说那八个字"）。**例外**：节目社群黑话（挖坑/填坑/催更/课代表）是原节目主播自己的口头禅，合法。**强制自查**：每幕写完机械执行 `grep -n "幕\|伏笔\|彩蛋\|板块\|环节\|回收\|收束" 幕文件`，逐条裁决（"夜幕"等自然语也建议换词，零容忍最省心）——v5 实战教训：写作时自觉绕开了"下一幕"，却写出"今天四幕""埋个伏笔""埋个彩蛋"这类变体，人肉记忆靠不住，必须机械扫描。
3. **禁止书面腔**：这是要说出来的稿子。允许"这个事吧""你就想啊""说白了"；句子短；避免书面语与四平八稳的排比。
4. **主持人不是捧哏**：主持每轮话要承接上一轮具体内容（追问/复述/接梗/讲自己），禁止纯应和（"对""是的""嗯"单字轮）。
5. **分寸底线**：吐槽有爱、刻薄有度；沉重话题一句带过不消费；敏感题材配立场双轨声明、幽默对象隔离（详见 04/05）。
6. **单一真相源**：台词修改只改 md 源稿，txt 用 `scripts/md_to_timeline.py` 重新生成，严禁手改。
7. **纯双人与引语转述**：全稿只有两位说话人；历史人物的话一律第三人称转述（"张璁说，……"），**不写引号直接引语**——合成引擎（豆包 action=3）遇直接引语或叹号密集的角色台词会自主触发戏剧化第三音色（《笑谈历史》EP05 多版返工实证）。每幕写完机械扫描 `grep -n "“\|”\|「\|」" 幕文件`，逐条裁决。

**B 组·风格倾向（软性，统计自原节目，服务于生动，不用于限制）：**

7. 认知反差可帮助选题，但只有证据确实改变原判断时才使用。
8. 观点姿态：敢下判断+概率化表达（"我认为概率最大""不好说"）；争议给平衡；预测只给可能性清单。
9. 结构是"骨架"不是"轨道"：冷开场+报幕缘由+主体+收束+结尾菜单是常形，但原节目也常不守常形（连载直接书接上回、情怀期放歌收尾）——形态服务于内容。
10. 跑偏是魅力不是事故：旁征博引的枝蔓（讲到 A 岔到 B 的典故/掌故/生活经验再绕回来）多多益善，主讲自我觉察式拉回（"话题扯远了"）是收束技巧不是配额。
11. 以古鉴今：知识尽量能落到听众生活（一两句点到即可），结尾常有一个可带走的工具或行动——但故事与畅聊永远优先于"应用栏目"（v3 教训：说教压死生动性）。

产出文件默认保存到用户项目目录（如 `podcasts/` 下按 `EP{编号}_{主题}` 建目录），包含：`选题卡.md`、`大纲.md`、各幕 `脚本_第N幕.md`（唯一源稿）、各幕 `第N幕_时间脚本.txt`（生成物）、`质检报告.md`、`output/`（各幕与完整版的 mp3/srt/时间轴 json）。

## 完成一期的标准

- 选题卡：核心问题明确、标题与冷开有证据支撑、听众值得听的理由具体
- 大纲：全期发现路径清楚，关键转折有证据，两位主播的认识起点不同
- 脚本：事实、推断、演绎有界；关键结论有来源；两人互相回应且能改变判断；全文朗读顺口；结尾与本期故事相称
- 质检：关键事实经独立反证审稿；剩余不确定性明示；清单记录证据与修订；盲听或盲读反馈已处理
- 音频（若做阶段 E）：md→txt 链路一致（转换器重生成比对通过）；SRT 无剧本腔/尾注/旧句残留（正反向抽查）；幕间衔接试听干净；字幕条数 = 各幕话轮数之和
